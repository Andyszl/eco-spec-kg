# 固定适配器的监督学习诊断

本入口不训练、不换 checkpoint、不读取 dev/test 原文或标签来生成诊断单元。继续使用已按共享验证集 loss 选定的控制 checkpoint-80、修复 checkpoint-120，并与基座对照。

从已有 repair_train 和共享 validation 的目标中，确定性选择所有包含“变量→方法/来源”参考正边的单元：7 个训练视图、3 个内部验证单元，共 10 个。每个都检查完整 v214 候选图；其中 6 个训练/验证问题隔离过未知关系，因此额外保留精确原问题作配对诊断。共 16 个问题、三模型 48 次请求，同一问题的候选、提示及解码在三模型间一致。

比较原问题与完整问题时只恢复既有隔离关系，不改正文/提示/候选规则/适配器。原问题仅作离线诊断，不用于修改正式推理的完整图。两视图及多个变量共享同一父单元，不能合并视为独立样本。内部验证仍参与过方案选择，CHM 三种 DEM 拼写也只对应一个逻辑来源。

分别报告参考正例命中、明确审核排除项选中、未知候选选中、其余监督未选项选中。后两类不称为已确认 FP。审核参考复用现有标签及助手审核，不是新独立人工金标；正例未命中不直接证明唯一因果原因。

继续使用 3072 输出预算和相同 unique 解码，诊断部署预留 16384 上下文，避免长训练问题无充足生成空间；这不是正式 8192 dev 协议，不重新计算或替代失败门槛。所有生成必须正常 stop 且通过响应证明/候选成员/预测证据检查，失败不输出完整 summary。

启动前校验固定训练 manifest、完整输入/原预检/代码/适配器及本诊断 case hash，检查 GPU0 和 8018 空闲，只清理自己启动的服务。自动打包新结果目录并经 Git 回传，不包含权重。运行后只回传 RESULTS_UPLOAD_OK、PROBE_EXIT_CODE、PROBE_DIRECTORY；失败时另附末尾错误。

本地已用合成小适配器和模拟 HTTP 验证 48 请求完整执行、两视图、正例/未知/明确排除分离及坏响应/证明拒绝；也检验 GPU 占用保护和本地裸 Git 成功/失败回传。尚无本诊断的服务器实测结果。
