# 新一轮语义监督 seed42 配对

本轮将训练来源中的变量获取方法、数据来源关系作为监督修订对象。冻结数据与历史结果保留，派生输入放在本目录；新增标签由助手对原文审核，不能称为新增独立人工金标。

两组各625条训练记录，来源单元、候选v2.11、提示v2.6、证据定位和长视图完全相同；只有4个训练单元的监督目标改变，新增4条正例：K_EPIC的获取模型、Q_sr的RUSLE方法、SR的修正风蚀方程方法、P_i,j,k的降雨资料来源。未把所有方法备选、间接中间量或NDVI端元来源批量翻为正例。

共同验证集保留原69条内部验证，再从原train留出整个FVC公式单元，合计70条。该单元原有获取方法正例，另审核增加FVC输出的遥感图像流程来源；两个候选都实际进入assistant目标。该来源及任何子视图均不出现在两组train，其13条原文行与训练无重叠。这个来源曾参与此前开发，因此是新配对中的训练排除验证，不是未使用来源的最终测试。

|实际目标覆盖|变量→方法正例|变量→来源正例|
|---|---:|---:|
|对照train|1条／1个父来源|2条／1个父来源|
|修复train|4条／4个父来源|3条／1个父来源|
|共同validation|1条／1个父来源|1条／1个父来源|

来源正例的训练父来源仍少，当前只适合小规模配对筛选，不能声称广泛泛化。FVC来源按原文明示的像元分解计算流程绑定到输出，未由共现推出NDVI_soil、NDVI_veg直接取自遥感图像。

候选生成只作两项通用补全：为已有“基于某模型/方程”提供去掉触发前缀的最小名称候选；为公式输出提供当前公式包提到的数据来源候选。两项都不自动建最终关系，保持由模型选择。没有新增开发实体、来源ID或公式编号专属规则。现有冻结结构模块保持原样。

执行顺序：

1. 在已激活ecospec-train的Linux服务器，获取交付时指定的固定Git提交，在新worktree执行`bash tools/run_semantic_preflight_20261015.sh`。它复查冻结文件、源代码、派生输入和分词器哈希，隐藏GPU，只加载本地processor，对625+625+70=1320条记录逐项编码，检查8192上限与有效监督。
2. 预检报告与日志自动打包，经独立Git分支回传。无论逐条长度成功或失败，都保留报告。回传RESULTS_UPLOAD_OK、PREFLIGHT_EXIT_CODE和PREFLIGHT_DIRECTORY后，由本地复核完整原始报告。
3. 预检通过后，再给出指向确切预检路径的训练命令。入口为`bash tools/run_semantic_pair_20261015.sh /absolute/preflight_report.json`，执行前再次核对输入、真实预检、Swift4.4.2参数、显式划分、GPU0空闲及BF16；任何条件失败均不启动训练。
4. 两臂均从原基座开始，seed42、每臂200更新、batch1/累积16、lr0.0002、r8/alpha16/dropout0.05、8192、每40步验证保存，按相同70条验证的最低loss选checkpoint。后续完整dev用同一候选/提示/结构模块，仍要求原严格门槛全部通过，才考虑三种子。

`input_manifest.json`保存每份输入SHA、来源源码LF SHA、原划分继承、逐条修订理由及证据、实际监督覆盖、共同验证策略与固定训练预算。本地测试里的mock编码不是真实长度检查；收到真实服务器预检前不宣称训练已就绪。本目录的validation具有角色覆盖，整体loss仍不能替代稀有关系的独立抽取评分和最终新来源测试。
