# EcoSpec-KG V2 正式实验命令链

## 1. 目标与隔离原则

V2 实验把数据生产、预测合法性检查和性能评测分为独立进程：

1. `extract-v2` 只读取 `blind/*_units.jsonl`。
2. `validate-predictions-v2` 只读取盲来源单元、预测和冻结 Schema。
3. `evaluate-v2` 在预测通过验证后才读取 `gold/*_annotations.jsonl`。

禁止把旧的 `gold/splits/units_test.jsonl` 传给抽取器，因为该文件同时包含
`source_unit` 和 `gold_annotation`。

## 2. 冻结实验数据包

在项目根目录执行：

```powershell
$env:PYTHONPATH = "src"
python -m ecospec_kg.cli_v2 prepare-experiment-v2 `
  --source-units results/dataset_v2_20260724/gold/source_units_enriched.jsonl `
  --annotations results/dataset_v2_20260724/gold/annotations_all_units.jsonl `
  --out data/frozen/v2.1 `
  --dataset-version v2.1 `
  --gold-nature ai_expert_pre_gold
```

冻结器生成：

- `blind/train_units.jsonl`、`dev_units.jsonl`、`test_units.jsonl`；
- `gold/train_annotations.jsonl`、`dev_annotations.jsonl`、`test_annotations.jsonl`；
- `schema_v2.json`；
- `manifest.json`，包含切分规模、文件 SHA256 和金标准性质。

盲测文件会剥离 `review_status`、`gold_nature` 等审阅元数据；若来源输入含
`gold_annotation`、`entities`、`relations` 或 `triple_id`，冻结命令直接失败。

## 3. 抽取 V2 预测

确定性规则基线：

```powershell
python -m ecospec_kg.cli_v2 extract-v2 `
  --units data/frozen/v2.1/blind/test_units.jsonl `
  --config config/experiments_v2/rule_baseline.json `
  --out runs/v2.1/rule_baseline/seed_42
```

输出包括：

- `predictions.jsonl`：每个来源单元一条预测；
- `resolved_config.json`：实际生效配置；
- `raw_responses.jsonl`：LLM 后端原始响应，规则后端为空；
- `run_manifest.json`：输入、配置、预测哈希及运行环境。

可选的 `llm` 后端只允许模型从结构感知规则生成的封闭候选实体和关系中选择：

```powershell
$env:ECOSPEC_LLM_BASE_URL = "http://gpu-server:8000/v1"
$env:ECOSPEC_LLM_API_KEY = "local-token"
$env:ECOSPEC_LLM_ENABLE_THINKING = "false"
python -m ecospec_kg.cli_v2 extract-v2 `
  --units data/frozen/v2.1/blind/dev_units.jsonl `
  --backend llm `
  --model Qwen3.5-9B `
  --out runs/v2.1/llm_selector/dev_seed_42
```

Qwen3.5 不使用旧的 `/no_think` 追加方式。`OpenAICompatibleProvider` 会在设置
`ECOSPEC_LLM_ENABLE_THINKING=false` 时向 vLLM 请求体写入
`chat_template_kwargs.enable_thinking=false`。

## 3.1 生成与 V2 选择任务对齐的 LoRA 数据

只允许使用盲训练来源单元和明确标记为 `split=train` 的训练标注：

```powershell
python -m ecospec_kg.cli_v2 prepare-lora-v2 `
  --units data/frozen/v2.1/blind/train_units.jsonl `
  --annotations data/frozen/v2.1/gold/train_annotations.jsonl `
  --out data/training/qwen35_v21_train.jsonl
```

命令拒绝 `dev` 或 `test` 标注，并生成同名 `.manifest.json`，记录输入哈希、
样本数和封闭候选的实体/关系召回上限。当前 V2.1 预金标包实测生成 693 条样本。
使用 `structure-aware-rule-v2.1` 时，训练集候选实体召回上限约为 0.9019，关系召回
上限约为 0.8148；开发集两项候选召回均为 1.0。关系候选上限仍未达到 0.9，论文
必须独立报告候选上限和选择器指标，LoRA 不得被描述为能够恢复候选集之外的关系。

## 4. 无金标验证

```powershell
python -m ecospec_kg.cli_v2 validate-predictions-v2 `
  --units data/frozen/v2.1/blind/test_units.jsonl `
  --predictions runs/v2.1/rule_baseline/seed_42/predictions.jsonl `
  --schema data/frozen/v2.1/schema_v2.json `
  --out runs/v2.1/rule_baseline/seed_42/validation
```

验证范围包括全量单元覆盖、Schema 类型与方向、关系端点、证据 span、重复记录、
抽取错误和答案字段泄漏。存在任一失败时命令返回非零退出码。

## 5. 独立严格评测

```powershell
python -m ecospec_kg.cli_v2 evaluate-v2 `
  --gold data/frozen/v2.1/gold/test_annotations.jsonl `
  --predictions runs/v2.1/rule_baseline/seed_42/validation/validated_predictions.jsonl `
  --units data/frozen/v2.1/blind/test_units.jsonl `
  --validation-report runs/v2.1/rule_baseline/seed_42/validation/validation_report.json `
  --out runs/v2.1/rule_baseline/seed_42/evaluation
```

评测器使用来源单元级严格键：

- 实体：`unit_id + name + entity_type`；
- 关系：`unit_id + head_name + head_type + relation_type + tail_name + tail_type`。

输出实体与关系微平均 F1、关系宏平均 F1、分类指标、标准级指标、单元完全一致率、
证据重叠率、公式路径、来源/单位边及质量约束边完整率，并保存逐条错误清单。

## 6. 结果使用边界

当前冻结包是 `ai_expert_pre_gold`。该链生成的指标用于软件验收、预实验和消融调试；
在两名真实领域专家独立复核测试集并完成裁决前，不作为论文最终性能结论。

此外，当前 HJ 1171、HJ 1174、HJ 1175 测试集已经在工程开发期间用于链路检查并查看过
预金标指标，因此现有运行结果只能记为 smoke/pre-experiment。论文正式外部测试应在方法、
prompt 和阈值冻结后，使用此前未参与开发且金标未向抽取进程开放的专家裁决测试集执行一次。
