## 2. 已确认并修复的代码问题

1. 对整段公式删除所有空白，会把`Caco\nEF`合并成`CacoEF`、把`r L`合并成`rL`。修复后保留标识符之间的空白，仅压缩明确的花括号下标，例如`x_{i, j}`。
2. 原标识符模式只允许拉丁/希腊字母，漏掉`实测值`、`反演值`、`验证点数`以及`R_半月k`、`S_L潜`。修复后识别完整中文符号，同时测试`总实测值`不能匹配为`实测值`。
3. `Q_se_p`和`x_i_j`被截断成多个标识符。修复后保留完整多层下标，并同步修正公式左端识别，避免将`se_p`当成`Q_se_p`的输出。

未恢复大小写混同、函数名子串匹配、按下标基名合并、无匹配就添加所有变量等旧行为。候选生成版本升至`structure-aware-rule-v2.4`，三个内置实验配置同步更新；提示策略版本不变。

新增14项回归用例在修复前11失败、3通过，修复后通过；相关64项、完整99项测试均通过。新增用例包含真实中文公式结构、嵌套下标输出及反向边界检查。未调用模型服务。

## 4. 本次补丁的实际影响与限制

相对665a4b1，仅5个训练单元发生候选变化，没有减少已覆盖的现有标注关系；新增覆盖9条：A.18输出EF（1）、REE的中文输入及单位（4）、A.22输入L（1）、A.1输入n和输出i（2）、A.6输出R（1）。

其中A.1的`has_output i`和A.6的`has_output R`虽然命中现有标注，却与原PDF的输出角色不符。本补丁修复词法识别后，这两条被现有左端启发式重新识别；并未解决求和下标赋值与真正输出的区分，也未恢复A.6丢失的下标。因此不能把“新增覆盖9条”写成“新增9条正确关系”，不能将覆盖上升写成模型质量提升。

后续必须同时审核来源结构和标注角色。不得为恢复旧分数而补回所有旧候选。历史分数只作对应输入和候选版本的记录。
